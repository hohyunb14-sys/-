# 방호현 에이전시

이 폴더는 방호현의 삶을 방(Room) 단위로 나눠 담은 곳이다.
Claude Code로 이 폴더를 열면 이 파일을 먼저 읽는다.

## 대표

- 이름: 방호현
- 본업: 장례지도사 (근무일이 불규칙 — 근무일 / 휴무일이 요일과 무관하게 섞임)
- 채널: 유튜브 "장례멘토 방호현" (장례 콘텐츠) + 자기계발 채널
- 관심: 장례 콘텐츠 제작, 건강/체중 관리, 사진 실력

## 절대 규칙

1. **지우지 않는다.** 이 폴더의 파일을 삭제하거나 덮어쓰지 않는다.
   고칠 일이 있으면 새 파일을 만들거나, 반드시 먼저 물어본다.
2. **방의 성향을 지킨다.** 각 방의 `CLAUDE.md`에 적힌 원칙과 "안 하는 것"을
   그 방의 결과물에 반드시 적용한다.
3. **다른 방 일이면 조율한다.** A방 자료로 B방 결과물을 만들 때는
   양쪽 원칙을 모두 확인하고, 무엇을 지켰는지 결과물 앞머리에 남긴다.
4. **근무일에는 요구하지 않는다.** 근무일이면 기록만 받고, 새 과제를 얹지 않는다.

## 폴더 구조

```
rooms/           방마다 폴더 하나. 결과물이 여기 쌓인다
  funeral-content/   장례 콘텐츠실
  health/            건강관리실
  channel/           자기계발 채널실
meetings/        회의록
depts/           부서 시너지 산출물 (여러 방을 합쳐 만든 것)
daily/           날짜별 브리핑 원본
team.md          조직도 — 누가 어느 방에 있고 직급이 무엇인지
```

## 결과물 파일 형식

`rooms/*/` 안의 `.md` 파일은 앞머리에 이렇게 적는다.

```
---
결과물: 대본 초안
태그: 대본, 장례, 촬영
작성: 서진 실장
출처: 2026-08-25_수의-가이드.md      (파생이면 원본 파일명)
원칙: 자극적인 제목 제외              (조율했으면 지킨 원칙)
---
```

파일 이름은 `YYYY-MM-DD_짧은-제목.md`.

## 화면으로 보기

`node scan.mjs` 를 돌리면 이 폴더를 읽어 `state.js` 를 만들고,
`office-map.html` 을 열면 이 폴더가 게임 화면처럼 보인다.
스캔은 **읽기만** 한다.

## 진행 상황을 물어보면

"요즘 뭐 하고 있어" "장례 콘텐츠 뭐 진행 중이야" 같은 질문을 받으면:

1. 답은 평소처럼 대화창에 바로 한다.
2. **그리고** 그 방(들) 폴더에 `진행상황-YYYY-MM-DD.md` 파일도 함께 남긴다.
   이미 오늘 날짜로 만든 게 있으면 새로 만들지 않고 그 파일에 이어 적는다.
3. 형식은 결과물 파일과 동일하게 앞머리를 붙인다.

```
---
결과물: 진행 상황 요약
태그: 진행상황
---
```

이렇게 하면 단순히 물어본 것도 오피스 맵 화면에 남아서,
나중에 방을 클릭했을 때 "그때 뭐가 진행 중이었는지"를 다시 볼 수 있다.
